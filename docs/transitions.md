# 动作衔接与回放

`collision.py` 负责几何检查、绕行搜索和平滑；`transition.py` 连接两段动作。衔接输出可直接交给现有 `replay` 执行。日常回放可直接按顺序传入多个文件，由 `replay` 自动规划，无需手动衔接。

## 使用

Linux Python 3.11，使用 OMPL 2.0.1 和 MuJoCo 3.15+，在项目根目录运行：

```bash
python -m pip install -e '.[planning]'
g1-action-studio transition examples/transition/action-a.json examples/transition/action-b.json \
  --side left --clearance 0.02 \
  --max-velocity 0.5 --max-acceleration 2.0 \
  --output data/transition-preview.json
```

输入可用 `teach` 示教录制，或 `build` / `transition` 生成的统一动作。程序对两段动作重采样，使动作边界缓慢停住；
默认 `--speed-scale 1` 保留各动作时长。另一侧手臂统一保持动作 A 首帧姿态，忽略原记录中另一侧的漂移。
如需核对真实站姿，`--body-pose data/body-pose.json` 接受 J0–J14 的 15 个弧度值数组。
该姿态在完整规划期间保持不变。未提供时明确使用参考零位，不推测现场姿态。

结果包含完整的 `action_1 → transition → action_2` 帧序列、过渡路点、速度/加速度指标、
模型哈希、最小间隙及规划参数。输出为 `g1-arm7-dex3-action-v1`，`kind=sequence`；单个动作是同一格式的 `kind=single`。
成功为 `offline_collision_pass`，表示制作时的模型检查通过。制作过程不连接 DDS，不覆盖现有文件；失败不输出动作。

总时长为 A + 衔接 + B。例如 10 秒与 6 秒动作，衔接耗时 2 秒，则输出 18 秒；端点相同则为 16 秒。
组合输入还可与下一个动作继续衔接。合成示例标记会保留到输出，禁止真机执行。

```bash
uv run --extra planning g1-action-studio replay eth0 data/my-combined.json \
  --profile data/my-replay-profile.json --output data/combined-run.json --execute
```

无需独立审核命令，也不强制先运行预览。执行自动读取当前双臂及 J0–J14 姿态，固定另一侧手臂，
重新规划当前姿态到动作起点、动作终点到当前姿态的路径，并检查整个目标序列。
一次接管后播放完整组合，最后一次回位、释放。未指定 `--side` 时自动使用组合文件的回放侧；不允许切换到另一侧。
执行中腿/腰相对规划姿态偏离超过 0.02 弧度时停止，反馈不可信时不盲目发送恢复动作。

## 规划流程

1. 检查动作 A 末帧和 B 首帧的关节范围与几何间隙。
2. 优先尝试关节空间直连。遇到碰撞或余量不足，用 OMPL `RRTConnect` 搜索绕行路径，单次搜索预算默认 5 秒；只接受到达目标的完整解。
3. OMPL `reduceVertices` 简化路点，`smoothBSpline` 做空间平滑。搜索、简化和平滑均通过自定义 `MotionValidator` 调用同一个 MuJoCo `edge_clear`，不使用默认离散采样代替区间检查。
4. 沿每条安全线段做五次时间插值，按速度、加速度上限计算时长。路点处解析速度、加速度为零。
   时间参数化保持 OMPL 输出的分段路径，空间平滑产生的新连接已由碰撞检查确认有效。
5. 检查两段完整动作、过渡及所有帧间区间，再保存结果。

碰撞检查使用 MuJoCo 的凸几何距离查询，不依赖仿真接触过滤器。每段区间从中点检查，
以“转角 × 下游最大半径”界定各几何体的位移，再界定几何对距离的变化。
距离足以覆盖整个区间才通过，否则二分继续检查。达到细分预算仍不能证明安全时拒绝。
因此不是“每隔若干帧看一下”。距离查询另留 0.1 毫米数值余量。

## 模型范围

- 使用宇树公开的 G1 29DoF + Dex3-1 安装结构、关节轴和 STL 外形。
  机体、头、双腿、双臂和掌部都参与检查；每份 STL 按凸包计算，可能比实际外形更大。
- 手指使用宇树官方Dex3-1的14个关节、关节范围与碰撞几何；不再使用六个球形包络。
  拇指中段保留官方可视网格与碰撞box，group=1仅显示、不加入碰撞组合。手指角度与手臂一起录制、插值和执行。
- 同一刚体和直接父子刚体不相互检查。手部内部（同侧手指、手掌、腕部）的非相邻组合仍检查穿透，但不套用2厘米余量；
  对手指与身体、另一侧手的组合仍使用全局余量。查看器地板不属于本体检查范围。
- 肩部 roll 外壳与躯干、同侧肘部与 wrist pitch 外壳、同侧 wrist roll 与 wrist yaw 外壳
  仍检查穿透，但不套用全局 2 厘米余量：这些安装区域在正常姿态下本就只有数毫米间隙。
  `minimum_mount_gap_m` 单独报告。两个最小间隙字段统计采样姿态；帧间区间另外通过运动界限证明满足要求，
  不把采样最小值当成连续运动的精确最小距离。
- 固定机体和腿/腰姿态，空手，无环境障碍。额外安装件、线缆、衣物或负载没有模型；行走、倾斜变化、
  环境碰撞、动力学、平衡和真实跟踪误差不在此结果范围内。

公开模型尚未按具体实机外形和安装尺寸验收。离线通过仅针对上述模型和固定姿态，
不能宣称真机绝不会碰撞。自动衔接虽已接入真实回放流程，实际跟踪、负载、机体稳定和控制交接仍需在本机确认。

## 验证案例

`examples/transition/action-a.json` 和 `action-b.json` 是合成案例：端点无碰撞且满足余量，
直接连接在中途穿入骨盆附近。OMPL 搜索生成绕行路径，具体路点可能随运行变化。测试检查端点、直接段失败、
绕行段与完整序列通过、速度/加速度上限、另一侧固定、动作内部碰撞拒绝、无路径拒绝和禁止输出覆盖。
这些例子不用于真机执行。

原手写 RRT 的随机种子与迭代次数参数已删除，`transition` 不再提供 `--seed`。动作文件格式、示教与回放操作保持不变。空间平滑使用 OMPL B-spline。`parameterize_path` 仅负责运动时长、速度/加速度约束和 50 Hz 时间采样；它不再承担空间路径优化。当前仍在输出路点处停稳，不实现不停顿轨迹混合。
