## 01：集中控制布局定义，保持既有 Dex3 流程

### Description

当前业务以全局固定 28 关节定义贯穿动作处理、规划、反馈和命令发送。先将布局语义集中到不可变 JointLayout，再保持现有 Dex3-1 用户行为，为后续仅手臂路径提供明确接口。本卡是必要的前置重构，不新增仅手臂 CLI 功能或改变输出 schema。

基线为 main 的 f9a7b8d。使用 Python 3.11 和标准库，不添加运行依赖、插件注册表、继承体系或全局模式切换。

### Demo path

在同一进程中分别取得独立的 Arm7 与 Arm7 + Dex3-1 布局，验证侧索引和名称；使用显式 Dex3 布局走通既有动作规划和模拟执行，无需修改全局变量。

### Acceptance Criteria

- [ ] 提供不可变布局解析入口，包含 profile_id、joint_names、左右侧索引和可选手部型号；关节数量从名称推导。基线尚无该入口，新增契约测试在基线不能通过。
- [ ] 在同一测试进程交替使用两个布局对象，14／28 维校验及左右侧索引相互独立；试图修改不可变字段失败，未知 profile 明确拒绝。
- [ ] 将既有 28 关节动作校验、规划、快照和执行调用链改为显式布局，测试可断言该链路不再读取可变全局布局；保留旧输入和输出行为。
- [ ] 插值对起止长度不一致报错，帧计算对跨帧维度不一致报错，不能由 zip 静默截断；新增负例在基线失败。
- [ ] 不增加仅转发调用的兼容包装；若过渡阶段需要保留旧常量，消费方迁移后在本卡内清理，最终不留两套布局来源。

### Regression checks

既有 Dex3 顺序、手臂 J15～J28、权重槽位 29、CRC、增益、超时和释放行为保持不变。运行受影响回归与 Ruff；这些是保持行为的检查，不冒充新增功能。

### Blocked by

无。

### Priority

high

### SPEC Reference

第 2 节职责划分；第 3.1 节布局；第 5.1 节内部接口；第 10 节 S1。

## 02：制作并读取仅手臂动作，同时兼容旧 Dex3 文件

### Description

让用户可以检查仅手臂 profile，并通过 build 将完整 14 关节录制制作成 v2 动作。集中归一化旧 Dex3 文件，不在各业务模块分别识别旧格式。本卡不承诺仅手臂规划、示教或实际回放已完成。

配置沿用 --profile；target_profile 选择 unitree-g1-arm7 或 unitree-g1-arm7-dex3-1，collision_hand_model 本期只支持 dex3-1。新结构 schema 分别为 g1-action-studio-control-profile-v2、g1-action-studio-recording-v2、g1-action-studio-action-v2、g1-action-studio-replay-plan-v2。

### Demo path

通过不执行的参数检查接受一份无手部增益的 Arm7 profile；运行 build 将 14 关节录制生成带布局、摘要和统计的动作，再加载该动作；旧 28 关节动作仍可加载。

### Acceptance Criteria

- [ ] 仅手臂 profile 缺少全部 hand_* 增益时通过检查，且不初始化 SDK；仍需验证手臂参数。新增命令测试在基线不支持该配置。
- [ ] 仅手臂 profile 中出现已知 hand_* 增益、未知 profile、缺少碰撞型号或型号不支持时明确拒绝；Dex3 profile 仍要求完整手部参数。
- [ ] build 接受合法 14 关节 v2 录制并独占生成 v2 动作；关节名、控制布局、碰撞型号、首末实测姿态和时间轴可断言，摘要可重新计算验证。
- [ ] 接受现有旧 Dex3 录制和动作，在入口验证后归一化，构造的新动作输出 v2，源文件字节不变；未变动的帧维持原轨迹摘要。
- [ ] 新格式要求 q／dq 维度和 joint_names 顺序准确；28 维数据伪装为 Arm7、错误顺序、损坏摘要、已有输出均有自动负例，且不会截断、补零或覆写。
- [ ] 配置只读取一次，返回值保留布局与碰撞设置；新增测试能观察到这些字段，而不是只取得增益。

## 03：使用完整手部活动包络规划仅手臂动作

### Description

仅控制 14 个手臂关节，但真实安装的手仍占空间。按确认的几何上界构造手指包络，复用实际掌部，贯通 transition 命令、规划、完整轨迹和帧间检查；不能靠零位手指或扩大排除规则获得通过。

首版每个原手指碰撞几何生成一个以该手指首关节安装点为中心的保守球。半径为运动链固定平移长度之和、几何局部偏移长度、几何包围半径与 0.0001m 余量之和。球固定在手腕坐标系，保留来源几何与连杆元数据。

### Demo path

提供两个合法、不同姿态的 14 关节动作，通过 transition 命令生成非零过渡，输出 v2 组合动作，记录完整活动包络策略；另一个碰撞输入被拒绝。

### Acceptance Criteria

- [ ] 针对当前模型验证转动关节、关节原点和链路假设；不满足公式前提的合成模型被明确拒绝。按几何三角不等式说明覆盖上界，限位端点和随机姿态仅作为辅助回归。
- [ ] 模型受控维度为 14，掌部及手指包络仍参与外部碰撞；自动测试能检出躯干、对侧手／臂、非安装区同侧手臂碰撞。
- [ ] 保留几何来源映射，仅排除同手包络内部及明确的安装关系；将全部包络放在手腕刚体上不能导致同侧手臂整体被排除。
- [ ] 包络几何纳入上游手臂关节的帧间位移上界，构造端点无碰撞但帧间碰撞的输入时规划拒绝。
- [ ] 在真实 MuJoCo／OMPL 下，由命令入口生成至少一条非零的 14 关节过渡，组合文件能重新加载，输出包含 full_range_envelope、模型摘要和算法参数。
- [ ] 输入动作的布局或实体手型号不一致时在搜索前拒绝，原 28 关节模式继续使用其原有姿态几何检查。

### Failure gate

若首版球包络导致常用起始姿态全部不可用，不得以“实现了包络”关闭本卡；提交诊断供重新评审。不得缩小半径、扩大排除或转为固定手型。本卡未通过将阻塞示教和回放交付。

## 04：在无手部能力的 SDK 下完成手臂反馈和命令收发

### Description

让 SDK 端口按 profile 的布局只使用实际需要的协议。在仅手臂模式下，SDK 不必提供 HandCmd、HandState 或手部工厂，仍能接收身体消息、形成快照、发送手臂命令并关闭资源。本卡通过内存 SDK 演示协议适配，不提供新的现场诊断 CLI。

### Demo path

构造完全不包含手部类型的内存 SDK，加载仅手臂配置，推送身体反馈，等待就绪、读取 14 维快照、发送一个完整手臂命令并关闭端口。逐项检查创建的通道和命令内容。

### Acceptance Criteria

- [ ] 仅手臂端口在没有任何手部能力、没有任何手部消息的替身上成功就绪，q／dq 长度为 14，at 来自身体消息；新增测试在当前固定 28 维端口上失败。
- [ ] 真实 SDK 绑定的仅手臂初始化不导入手部类型；启用 Dex3 时才加载，重复初始化幂等，缺少能力在创建控制发布器前失败。
- [ ] 仅手臂状态和命令观察通道、发布器清单准确，手部订阅／发布／写入数为零；访问手部工厂立即抛错的替身仍可完成收发。
- [ ] 发送的 14 个目标准确写入 J15～J28，权重写入槽位 29，沿用 CRC；错误目标维度在任何 Write 调用前拒绝。
- [ ] 身体断流、非有限值、模式改变在仅手臂布局下被拒绝；Dex3 布局仍保留左右手原始映射、最旧时间及任一手缺帧失败。
- [ ] 仅手臂部分初始化失败能清理已有通道，一个资源关闭失败不妨碍其他资源清理；自动测试禁止真实 DDS 网络连接。

## 05：完成仅手臂示教、录制和避碰回位

### Description

将仅手臂 profile 接入现有完整示教流程，共用业务状态机，不复制另一套 teach。选中侧仅有 7 个手臂关节，另一侧保持基线。全程无手部增益要求和手部命令。

### Demo path

从 teach 命令入口加载仅手臂配置，在模拟 SDK 和人工输入替身下完成接管、软化、两次回车录制、终点保持、恢复刚度、真实几何回位规划、稳定和释放，生成可被 build 读取的 v2 录制。

### Acceptance Criteria

- [ ] 命令入口能用无 hand_* 参数的合法配置执行完整模拟示教；左、右两侧各有测试，所有阶段被观察到。
- [ ] 每帧保存 14 个真实模拟反馈位置和速度，准确记录 joint_names、target_profile、collision_hand_model；另一侧手臂不被选中侧示教增益影响。
- [ ] 回位使用实际模拟基线和身体姿态，通过包络避碰规划及稳定检查，不替换规划结果为成功。
- [ ] SDK 手部通道与命令数全程为零，录制文件可由 build 制作动作，报告明确手部控制未启用而非手部释放成功。
- [ ] 新增仅手臂异常测试覆盖录制输入 EOF、身体断流、回位规划失败和提前停止；关闭、信号恢复和错误提示保持既有语义，不生成冒充成功的录制。
- [ ] 接管条件、反馈超时、50Hz 调度和异常释放策略未被本功能顺带修改；Dex3 既有示教回归通过。

#3、#4。

### Priority

### SPEC Reference

第 4 节录制；第 5.5 节阶段流程；第 6 节几何；第 7 节报告。PRD US-003。

## 06：从命令行预览并回放仅手臂动作

### Description

把 14 关节动作接入用户可用的 replay 命令，包含单动作、多动作拼接、接管前规划、另一侧保持和回位。修正当前 CLI 位置参数与回放函数签名不一致的问题，改为关键字传参。

### Demo path

从命令行预览两个兼容的 Arm7 动作，核对输出文件和包络报告；再在无手部能力的模拟 SDK 中以执行入口完成回放，生成带反馈和模式说明的报告。

### Acceptance Criteria

- [ ] CLI 明确将 --output、--side、--speed-scale 和 --execute 映射到对应关键字；新增入口测试验证传入值不发生错位。
- [ ] 合法 14 关节动作使用仅手臂 profile 可离线预览；不导入真实 SDK、不初始化 DDS，报告目标数量为 14 且硬件未启用。
- [ ] 模拟执行从当前身体反馈生成基线，使用真实包络规划，完成非零单动作和多动作回放及回位；手部通道／命令数为零。
- [ ] 输出报告区分规划与执行指标，包含 hand_control_enabled=false、碰撞型号、包络策略；保留 release_sent、handover_confirmed 的真实语义。
- [ ] 14／28 动作混用、动作与 profile 不匹配、实体手型号不匹配均在创建控制发布器前失败；合成示例仍不允许被当作真机动作执行。
- [ ] 自动用例覆盖仅手臂跟踪偏差、身体断流、输出文件存在和控制周期失败；不得绕过执行器验证或无授权初始化网络。

### Blocked by

#3、#4。

### Priority

high

### SPEC Reference

第 4.3 节布局匹配；第 5.5～5.6 节执行与 CLI；第 7 节报告。PRD US-005。

## 07：在 Linux CI 验证完整流程并交付配置与使用说明

### Description

建立从用户命令入口到最终文件和模拟执行报告的连续验收场景，串联所有已交付行为，不仅重复单模块测试。提供仅手臂和 Dex3 两套配置示例，更新迁移与交接说明。

### Demo path

在新建的测试工作目录运行一项 Linux CI 验收：模拟示教生成录制，build 生成动作，transition 制作组合动作，执行离线预览和模拟回放，最后核对报告、摘要和资源记录。

### Acceptance Criteria

- [ ] 新增一条自动 E2E 场景串联 teach → build → transition → replay 预览 → 模拟执行，沿途使用前一步真实输出，不能替换业务或规划成功结果。
- [ ] 仅替换 SDK、时钟及人工输入，使用真实 MuJoCo／OMPL；不提供任何手部反馈或消息类型，整个流程断言零手部通道及命令。
- [ ] 连续核对 14 关节布局、首末姿态、摘要、输出数量、包络元数据和报告成功状态；至少有一段非零运动。
- [ ] 同一验收组覆盖布局不匹配的命令入口失败，以及身体断流后的执行失败与资源清理；失败不会生成宣称成功的结果。
- [ ] Linux CI 明确安装规划依赖，并将该 E2E 的依赖缺失或跳过视为验收失败；测试建立并清理独立数据，禁止访问真实 DDS 网络。
- [ ] 提供两类可通过参数检查的完整配置示例与对应 CLI 命令，说明旧文件读取、新格式输出和禁止布局自动转换。
- [ ] 更新交接说明，不再宣称仅手臂功能尚未实现；明确未控制手部不等于卸力，离线／模拟通过不等于真实控制权与交接验收。
